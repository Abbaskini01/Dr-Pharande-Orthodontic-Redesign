# ADR-004 — Adopt WCAG 2.2 AA Accessibility

**Status:** Accepted

**Date:** 30 July 2026

**Decision Makers:** Product Team

---

# Context

Healthcare websites must be usable by people with diverse abilities and assistive technologies. Accessibility should be considered a core product requirement rather than a post-development enhancement.

---

# Decision Drivers

The following priorities guided this decision:

- Inclusive user experience
- Legal and ethical considerations
- Improved usability
- Better SEO
- Long-term maintainability
- Consistent interaction patterns

---

# Decision

The project will target **WCAG 2.2 Level AA** compliance throughout design and development.

Accessibility requirements will influence component design, content structure, navigation, forms, and media.

---

# Alternatives Considered

## Basic Accessibility

### Pros

- Faster implementation

### Cons

- Inconsistent user experience
- Higher risk of accessibility barriers

---

## WCAG AAA

### Pros

- Highest accessibility standard

### Cons

- Significant implementation effort
- Not always practical for all content

---

# Rationale

WCAG 2.2 AA provides a practical and widely adopted accessibility target that balances inclusivity with implementation effort.

---

# Consequences

## Positive

- More inclusive website
- Better keyboard navigation
- Improved screen reader support
- Better semantic HTML
- Positive impact on SEO

## Trade-offs

- Additional testing effort
- More design constraints
- Increased development attention
