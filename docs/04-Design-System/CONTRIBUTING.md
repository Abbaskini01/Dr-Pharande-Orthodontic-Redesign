# Contributing Guide

## Purpose

This document defines how changes to the design system should be proposed, reviewed, and approved.

---

# Workflow

Idea

↓

Discussion

↓

Design Review

↓

Accessibility Review

↓

Engineering Review

↓

Approval

↓

Implementation

---

# Contribution Rules

All new components must:

- Follow naming conventions
- Include accessibility documentation
- Reference design tokens
- Include testing guidance
- Include revision history

---

# Pull Request Checklist

- Documentation updated

- Accessibility reviewed

- Responsive behaviour documented

- Tokens referenced

- Examples included

- Related documents updated

---

# Naming Conventions

Use PascalCase.

Example:

Button.md

Hero.md

Gallery.md

Avoid abbreviations.

---

# Version Control

Breaking changes require a major version increment.

Minor improvements require a minor version increment.

Documentation fixes require a patch version.
